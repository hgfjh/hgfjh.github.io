# Academic Site

A static academic homepage generated by Rust and Askama, hosted on GitHub Pages.
Public address: [oluolorode.com](https://oluolorode.com/).
Rust runs at build time only. Visitors receive HTML, CSS, a local WebP portrait,
a small optional video script, and the public CV when requested.

## Design and portrait

The design uses a compact midnight-blue masthead, ordinary links, and numbered
research entries. The selected IMG_7084 hybrid retouch is copied unchanged into
`static/images/portrait.webp` (750 × 1000). Only the optimized public image is
needed in the repository; keep the original and lossless master privately.

The portrait is loaded immediately with intrinsic dimensions to reserve space.
The genus-two surface is progressively enhanced using native WebGL 2. The
static schematic remains available without JavaScript or WebGL. The refined
double torus supports drag-to-reorient with quaternion rotation around a
body-fixed axis. Use the pause/play icon, arrow keys on the focused canvas,
or Home/double-click to reset. Open the adjacent orientation control to rotate
in 10-degree steps or reset without dragging. Rotation respects reduced motion,
tab visibility and scrolling.
No graphics library is loaded by the homepage.

## Genus-two mesh (Commits 8.2 and 8.5)

The Rust exporter constructs and checks a triangulation of the double of a
planar pair of pants, including edge orientation and circular vertex links.
A smooth waist deformation produces a more classical double-torus silhouette,
with additional projected-area and hole-fan checks for the PL embedding.
It writes `dist/static/meshes/genus2.json`; the homepage does not request
this inspection asset. See [the construction and proof](docs/genus-two.md).
No new dependencies are required. The optional Python reference check is
`python docs/check_genus_two.py`; it does not replace the Rust tests.

## Surface renderer (Commits 8.3–8.5)

The exporter also writes `dist/static/meshes/genus2.bin` and
`dist/static/surface.js`. The binary is 221,152 bytes at the current resolution,
including its 16-byte header. It retains every triangle and converts positions
and normals to f32 for rendering only. See [the renderer notes](docs/surface-renderer.md).

To preview locally after running the exporter:

```powershell
Copy-Item docs/surface-preview.html dist/surface-preview.html
python -m http.server 8000 --directory dist
```

Open http://localhost:8000/surface-preview.html for the standalone study, or
http://localhost:8000/ for the integrated homepage. The preview is intentionally
not copied by the exporter, so a fresh CI build does not publish the preview
page. The homepage uses the same renderer, with a larger responsive canvas,
no visible caption, and a minimal pause/play icon (Commit 8.5).
Run the JavaScript tests with Node 22+ (CI uses Node 24):

```powershell
node --test docs/surface-decoder.test.mjs docs/surface-rotation.test.mjs docs/surface-lifecycle.test.mjs
```

## CoxeterViewer5D

The academic homepage links directly to the independently deployed
[CoxeterViewer5D browser application](https://oluolorode.com/CoxeterViewer5D/).
Browser-supported operations require no installation. Native operations and
external research computations require the desktop or CLI workflows described
in the [CoxeterViewer5D documentation](https://github.com/hgfjh/CoxeterViewer5D).
The homepage loads no viewer assets, so the link adds no runtime dependencies
or startup overhead.

## Check and preview (PowerShell)

```powershell
cargo fmt --all -- --check
cargo clippy --all-targets --locked -- -D warnings
cargo test --locked
cargo run --release --locked
python -m http.server 8000 --directory dist
```

Open http://localhost:8000/ and check the portrait, advisor link, research,
CV, software link and mobile layout. The exporter copies the portrait to
`dist/static/images/portrait.webp`; CI checks that the copy matches the source.
The homepage uses automatically content-fingerprinted URLs for CSS, scripts,
portrait, mesh, favicon and sharing image. Stable aliases are retained for the
standalone preview and old pre-9 HTML. CV URLs remain stable. If an old HTML
page refers to a fingerprint from a prior deployment that no longer exists,
refresh the page; GitHub Pages controls HTML caching.

## Final audit (Commit 9)

After a release build, run `python docs/audit_site.py`. It verifies the actual
exported HTML, the asset inventory and fingerprints, unchanged portrait and
public CV, binary/JSON agreement, and the cold-resource byte budget. CI runs
`python3 docs/audit_site.py --strict` against its fresh output. The local audit
reports old build files but does not delete them. See [audit and acceptance
checks](docs/site-audit.md) for live checks and limitations. The public favicon
and sharing image are built from a custom SVG and the already approved public
portrait, respectively. No additional Cargo or npm dependencies are needed.

## Editing content

Use `src/content.rs` for profile information, papers and talks. For each paper,
optional resources are `None` until ready; change to `Some("...")`:

- `abstract_text`: approved plain-text abstract.
- `pdf_url`: approved public manuscript/DOI/arXiv URL; update status as well.
- `youtube_id`: actual 11-character YouTube video ID, with embedding enabled.
- `transcript_url`: public transcript URL.

The existing `static/videos.js` creates the privacy-enhanced YouTube iframe
only on activation. The ordinary YouTube link works without JavaScript.
Do not commit the private manuscripts or the original unredacted CV.

## Publish

The GitHub Actions workflow checks, exports, and deploys the site to GitHub
Pages on pushes to `main`.

## Custom domain (Commit 10)

The canonical origin is `https://oluolorode.com/`, defined in `src/assets.rs`.
Askama uses it for canonical/Open Graph metadata and the viewer links; the
sharing image URL also uses this origin. The independent Python audit and
Rust regression assertions intentionally pin the expected public address.
CSS, scripts, portrait, mesh and CV URLs remain relative for local previews.

Cloudflare Registrar/DNS and the GitHub Pages custom-domain configuration
are managed outside the repository. Use DNS-only records and GitHub's HTTPS
certificate. With a custom Actions publishing workflow, a committed CNAME
file is not required. Keep the GitHub domain-verification TXT record.

The viewer remains a separate GitHub Pages project; its expected inherited
URL is `https://oluolorode.com/CoxeterViewer5D/`. After configuring the domain,
verify that the homepage, CV, viewer, www redirect and legacy GitHub Pages
URL work over HTTPS. Test the viewer itself, not merely its landing page.
If a project has a separate custom domain, GitHub Pages inheritance does not
apply. No viewer source code or DNS settings are changed by this commit.
